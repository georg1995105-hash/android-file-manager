# Подпись APK и обновления

## Неизменные параметры

- `applicationId` = `io.personal.filemanager` — **не менять никогда** после первой постоянной установки.
- `versionCode` / `versionName` — только в `app/build.gradle.kts` (`appVersionCode`, `appVersionName`).
  `versionCode` строго растёт для каждого устанавливаемого обновления.

## DEBUG/TEST-подпись (неизменная)

- CI допускает только **исходный** debug-ключ (alias `androiddebugkey`, стандартный пароль debug `android`).
  SHA-256 сертификата: `07b0ea83a028f013c3a3d08e2e5138d3d8d2cd8fe22cb7b8378f5f00ae5bb588`.
  Кэш читается через `actions/cache/restore` без записи новых ключей. Скрипт `tools/restore_debug_keystore.sh`
  сверяет сертификат до сборки и не переписывает подходящий существующий keystore. При отсутствии ключа или
  другой подписи CI завершается ошибкой, не генерируя замену. Настроен `PFM_DEBUG_KEYSTORE_B64`:
  CI восстанавливает тот же исходный ключ из этого секрета (base64 от существующего `debug.keystore`),
  независимо от области видимости и срока жизни кэша.
- Старый кэш `pfm-debug-keystore-v1` был привязан к ветке `ccr-01aed2a6-se8umi` и недоступен из `main`.
  В CI #40305412451 cache miss привёл к генерации разных ключей в параллельных заданиях. Восстанавливать
  нужно исходный ключ из этой ветки/резервной копии, а не ключи из неудачного запуска `main`.
  Кэш может истечь или быть удалён; он не заменяет защищённую резервную копию у владельца.
- Перед установкой на эмулятор проверяются подписи текущего приложения, тестового пакета и предыдущего
  опубликованного APK. Проверка обновления: установка предыдущего APK → создание заметки → `adb install -r`
  нового APK → проверка заметки. Удаление приложения и очистка данных не используются.
- Точный диагноз, доступные отпечатки и ограничения проверки: [инцидент CI #40305412451](CI_SIGNING_INCIDENT.md).
- **Release-версию нельзя установить поверх debug без удаления приложения** (разные подписи). При удалении
  пропадут данные приложения (настройки, заметки, ссылки, избранное) — **перед этим сделайте резервную копию**
  в «Резервные копии» и восстановите её после установки release. Обычные файлы телефона не затрагиваются.

## Постоянная RELEASE-подпись

Создан один отдельный release-keystore: RSA 4096, срок сертификата 36500 дней.
SHA-256 сертификата: `d282ae0bb49c30bd848fcae3ae02533ff446a12ef7e3691863af53c4aa0ecda7`.
Это не DEBUG-ключ; прежняя DEBUG-подпись не менялась.

В GitHub Secrets настроены `PFM_KEYSTORE_B64`, `PFM_STORE_PASSWORD`, `PFM_KEY_ALIAS`, `PFM_KEY_PASSWORD`.
Значения не выводятся и не хранятся в Git. `tools/release-signing.sha256` содержит только публичный отпечаток.
`tools/build_signed_release.sh` восстанавливает ключ в собственном временном каталоге с правами 0600,
проверяет сертификат, собирает APK и удаляет временный ключ при любом завершении.
Конфигурационный кэш Gradle отключён для подписанной сборки. Готовые APK проверяются через `apksigner`,
на package ID, отсутствие debuggable и выравнивание 16 КБ; SHA-256 сохраняются в `SHA256SUMS.txt`.
Несовпадение сертификата или неполная конфигурация останавливают выпуск. Создавать замену нельзя.

## Выпуск и проверка обновления

Workflow `signed release acceptance` запускается из main (GitHub Actions → Run workflow).
Он собирает настоящий main и отдельную одноразовую следующую версию в временном worktree,
заново восстанавливая ту же подпись для второй сборки. На чистом эмуляторе проверяются install -r,
сохранение UID, заголовка и текста заметки. APK следующей тестовой версии не публикуется.
После успешной проверки публикуются только APK настоящего main, сертификат, SHA-256 и отчёт проверки
в приватном GitHub Release. Публикации в магазинах нет.

Перед каждым следующим устанавливаемым выпуском увеличивайте единственный `appVersionCode` в
`app/build.gradle.kts`; ключ и закреплённый сертификат сохраняются.

перенос данных владельца с DEBUG на RELEASE является отдельным действием и здесь не выполняется.
