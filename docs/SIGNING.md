# Подпись APK и обновления

## Неизменные параметры

- `applicationId` = `io.personal.filemanager` — **не менять никогда** после первой постоянной установки.
- `versionCode` / `versionName` — только в `app/build.gradle.kts` (`appVersionCode`, `appVersionName`).
  `versionCode` строго растёт для каждого устанавливаемого обновления.

## Сейчас: DEBUG/TEST APK

- CI (GitHub Actions) подписывает тестовые сборки debug-ключом, который хранится в кэше Actions
  (`pfm-debug-keystore-v1`). Тестовые APK обновляются друг поверх друга, пока кэш жив
  (GitHub удаляет кэш, не использованный 7 дней — тогда нужна переустановка).
- **Release-версию нельзя установить поверх debug без удаления приложения** (разные подписи).
  При удалении пропадут настройки приложения. Пользовательские файлы в памяти телефона не затрагиваются.

## До первой постоянной установки: release-ключ

Требования ТЗ §8: ключ создаётся один раз, хранится у владельца, резервная копия — отдельно;
в Git, логах, артефактах и чате ключа и паролей быть не должно.

Сборка уже поддерживает release-подпись без изменений кода:

- локально — файл `keystore.properties` в корне (в `.gitignore`):
  ```
  storeFile=/абсолютный/путь/pfm-release.jks
  storePassword=...
  keyAlias=pfm
  keyPassword=...
  ```
- в CI — переменные окружения `PFM_STORE_FILE`, `PFM_STORE_PASSWORD`, `PFM_KEY_ALIAS`, `PFM_KEY_PASSWORD`
  (из секретов GitHub; keystore декодируется во временный файл раннера).

Способ создания ключа и доставки его в секреты GitHub будет предложен владельцу отдельным шагом
перед выпуском первой постоянной версии (этап завершения ЭТАПА 1 / начало постоянного использования).

Документация: https://developer.android.com/studio/publish/app-signing
